How this site was built

A model, an agent and a few thousand blocks: rebuilding my homepage around the way I build software.

The old version of this site was fine. Dark background, a gradient, some cards, a timeline. It looked like a lot of developer homepages, because it was one. Then I read Samuel Rizzon's write-up of how he rebuilt his site, and sent Claude two links and one sentence: "I want to update my webpage with something like this."

Copying the right thing

His site is made of pixel blocks: the hero, the portrait, the little details. It's tempting to take the blocks. But the blocks aren't the idea. They're his: they come from Git City, his project that turns GitHub profiles into pixel cities. Copy them and you get his site with your name on it.

So the real question was: what's mine?

Three candidates

Claude came back with three options:

  • The site as a model. I lead BESSER, a low-code platform where you draw a model and generators produce the code. The homepage could be a UML class diagram of me that generates the real page.
  • An agent at work. A lot of my current work is about AI agents. The page could build itself like an agent's trace: a plan, then steps, then output.
  • Pixel blocks. The closest to Samuel's look.
// your call. which would you pick?

Good pick. I couldn't choose, so the site uses all three.

It turned out they weren't three ideas. They're one pipeline, the one I work on every day: a model goes in, an agent does the work, something gets built.

Model, agent, blocks

Blue is the model. When the homepage loads, a class diagram draws itself: class Armen, with attributes (role, base, languages) and operations, associated with Agent and BESSER.

Green is the agent. Under the diagram, a trace runs besser generate armen.buml --agent and reports each step as it works through the model.

Amber is the output. When the trace reaches generate, my name is emitted from the workbench as blocks. They come from real font pixels: the text is drawn off-screen, read back on a grid, and every filled cell becomes a block that flies to its place. The trace then reports how many blocks it placed. That number is counted at runtime, not typed in.

The name is made of blocks. Hover it and they lean away from your cursor. Click it and they scatter, then reassemble.

Esc skips the intro. If your system asks for reduced motion, you get the final frame straight away.

Resolution as a reward

Project covers start as coarse blocks and render on hover, stepping up through a few resolutions before the real image fades in. The two projects without a cover got pixel-art sprites instead: an antenna for 6G-TWIN and a decision tree for the interpretable-ML work.

The About section finishes the model joke. The class is in the hero; About is an instance of it, armen : Engineer, with real values filled in and an RPG-style special move.

A terminal instead of a form

The site is static, with no backend, so the contact section is a small terminal. help lists the commands. note <message> opens your mail client with the message filled in. My address is assembled in JavaScript so simple scrapers don't pick it up.

Some commands aren't listed in help.

Secrets

There are eight. The counter in the footer keeps score, and opening it shows a hint for each one you haven't found yet. Progress is saved in your own browser and never leaves it.

Stack

No framework, no build step. Plain HTML pages, two stylesheets and two scripts, served by GitHub Pages. Geist and Geist Mono for type, Font Awesome for icons. The diagram is hand-written SVG and the blocks are drawn on a canvas.

Who did what

I made the calls: the scope, the metaphor and what to keep. Claude Code (Claude Opus 5.5) wrote the code and drafted this post. It feels right for a page about generating things from a model to be generated too.
