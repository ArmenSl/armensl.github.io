BESSER in five minutes

What an open-source low-code platform actually does, and why the model is the source of truth.

BESSER is the open-source low-code platform I lead at the Luxembourg Institute of Science and Technology. This is the five-minute version of what it does and why it's built the way it is.

The problem with low-code

Low-code means writing less code by hand. You describe the application as models, and generators turn those models into working code. It's a good idea, but most low-code platforms are commercial. That brings vendor lock-in, limited extensibility, and generators you can't look inside.

BESSER takes the same idea and makes it open: you can read every generator, extend it, or write your own.

Model first

Models in BESSER are written in B-UML, a simplified, Python-based take on UML. Here's a tiny one: a city that tracks climate indicators. 

from besser.BUML.metamodel.structural import (
    DomainModel, Class, Property, Multiplicity,
    BinaryAssociation, StringType, IntegerType,
)

# classes and their attributes
city = Class(name="City", attributes={Property(name="name", type=StringType)})
indicator = Class(name="Indicator", attributes={
    Property(name="name", type=StringType),
    Property(name="target", type=IntegerType),
})

# a city tracks many indicators; each indicator belongs to one city
tracks = Property(name="indicators", type=indicator, multiplicity=Multiplicity(0, "*"))
owner  = Property(name="city", type=city, multiplicity=Multiplicity(1, 1))
city_indicators = BinaryAssociation(name="city_indicators", ends={tracks, owner})

model = DomainModel(name="Climate", types={city, indicator}, associations={city_indicators})
assert model.validate()["success"]

validate() checks the model before anything gets generated, so mistakes surface in the model, where they're cheap to fix.

One model, many targets

The same model feeds many generators. A REST API is three lines:

from besser.generators.backend import BackendGenerator

BackendGenerator(model=model, output_dir="./api").generate()
# → FastAPI endpoints + SQLAlchemy ORM + Pydantic models

Other generators produce Python, Java or Pydantic classes, SQL, Django projects, full-stack React + FastAPI web apps, Flutter apps, conversational agents, and Terraform for deployment.

Regenerating overwrites the output, on purpose. The model is the source of truth: change the model, not the generated code.

No Python required

Not everyone wants to write models in Python. The web editor lets you draw class diagrams, state machines, GUIs and deployment models, then click Generate and download the code. It runs the same generators as the Python API, and it can import a B-UML .py file, so the two ways of working connect.

Rules belong in the model

Some rules don't fit in a diagram: "an indicator's target can't be negative". UML has a language for that, OCL: 

context Indicator inv positive_target: self.target >= 0

B-OCL, the parser and interpreter we built for BESSER (paper), reads constraints like this one and checks them, so the rules live next to the model instead of being scattered through the code.

Try it

pip install besser   # Python 3.11+
