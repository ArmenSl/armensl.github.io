Why I love building agents

Software that doesn't just answer, it acts. And in BESSER, an agent is just another model.

A chatbot answers. An agent acts: it plans, picks a tool, uses it, checks the result and keeps going until the task is done. That shift, from software that talks to software that gets things done, is why I keep building them.

It started with impatience

My first serious agent was for me. Working on BESSER, I needed example models all the time, for demos, tests and documentation, and drawing each one by hand was slow. I wanted to describe a model and have it appear. So I built an agent that could do it.

That agent kept growing. Today it's the modeling assistant inside the BESSER web editor.

The modeling agent today

Open the BESSER web editor and there's a chat widget in the bottom-right corner. Behind it is the modeling agent:

  • It creates and edits diagrams: class, object, state machine, agent, GUI and quantum circuit diagrams, from a sentence.
  • It takes more than text: voice messages, and files such as PlantUML, knowledge graphs, images and PDFs, which it turns into diagrams.
  • It runs multi-step requests: "create a library system and generate Django code" becomes a plan: model first, then generator.
  • It writes rules too: describe a constraint in plain language and it adds it to the model as OCL.

Constraints make agents good

The biggest lesson from building it: an agent gets better when you give it less freedom, not more.

  • The language model only decides what goes in a diagram. A deterministic layout engine decides where it goes, so diagrams are tidy every time.
  • Its outputs are structured and validated, not free text that has to be parsed and hoped for.
  • It doesn't add things you didn't ask for. If you don't request a constraint, it won't invent one.
A demo can surprise you. A tool shouldn't.

An agent is just another model

This is my favourite part. In BESSER, an agent is modeled like everything else, as states, intents and transitions, and then generated. The modeling agent itself is built on BESSER's own agentic framework. So the same project can produce a web application and the agent inside it: what our ICWE 2026 paper calls smart web applications.

Agents everywhere

Once you start, you see jobs for agents everywhere:

  • A spec agent for the step before the model: getting the specification right.
  • An agent at home that runs my domotics. Same idea at a smaller scale: give it tools, let it act.
  • This website. The hero is a small agent trace that reads a model and generates the page. See how this site was built.

Every one of them started the same way: something I did by hand, often enough that it was worth building a tool for it. Lately the tool tends to be an agent.
